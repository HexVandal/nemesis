# Getting this onto GitHub

The archive you downloaded is the complete repository, **with its git history
already in place** — four commits, `main` checked out, everything committed.

## 1. Create the repository

Create an empty repo on GitHub. Do **not** initialise it with a README, a
`.gitignore` or a licence — this archive already has all three, and a
pre-initialised repo will make the first push fail with a divergence error.

## 2. Push it

Extract the archive, then:

```bash
cd nemesis
git remote add origin https://github.com/HexVandal/nemesis.git
git push -u origin main
```

If you use SSH:

```bash
git remote add origin git@github.com:HexVandal/nemesis.git
git push -u origin main
```

## 3. Replace the placeholder org name

Badges and links point at `HexVandal/nemesis`. If you rename the repository or move it
to an organisation, replace it everywhere:

```bash
# macOS
sed -i '' 's|HexVandal/nemesis|<new-owner>/nemesis|g' README.md CONTRIBUTING.md pyproject.toml
git commit -am "Point docs at the real repository" && git push

# Linux
sed -i 's|HexVandal/nemesis|<new-owner>/nemesis|g' README.md CONTRIBUTING.md pyproject.toml
git commit -am "Point docs at the real repository" && git push
```

Until you do this, the **CI badge will show as broken** — it links to a
workflow run that does not exist yet.

## 4. Check that CI passes

Go to the **Actions** tab. The workflow runs:

| Job | What it does |
|---|---|
| `lint` | `ruff check` over `nemesis/`, `tests/`, `examples/` |
| `test` | `pytest` on Python 3.10, 3.11, 3.12 and 3.13 |
| `build` | builds the wheel and sdist, uploads them as artifacts |
| `publish` | only on a tag — publishes to PyPI if you add `PYPI_API_TOKEN` |

The first run takes a few minutes. Every one of these jobs is green locally —
`270 passed`, ruff clean, wheel builds.

## 5. Recommended repository settings

- **About** → description: `The offensive-security scanner that thinks like a
  red team. Every finding ships with the experiment that proves it.`
- **Topics**: `security`, `pentest`, `scanner`, `vulnerability-scanner`,
  `bugbounty`, `sast`, `sca`, `red-team`, `offensive-security`, `python`
- **Social preview** → upload `assets/social-preview.png` (it is exactly
  1280×640, which is the size GitHub wants; the banner is 1280×340 and will
  letterbox)
- Enable **Discussions** if you want a place for capability-map feedback
- Enable **Private vulnerability reporting** under Settings → Security

## 6. Before you point it at anything

`nemesis` sends real attack payloads. Read `SECURITY.md` and the *Responsible
use* section of the README. Scope is default-deny, but the responsibility for
having authorisation is yours.
